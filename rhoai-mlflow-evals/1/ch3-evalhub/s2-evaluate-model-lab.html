Lab: Evaluate a Self-Hosted Model

Objective

Run evaluation jobs on a self-hosted model using EvalHub, monitor their progress, and inspect results and metrics from the RHOAI dashboard.

Pending review

Before you begin

You need access to the predeployed Red Hat OpenShift AI (RHOAI) instance provided in your lab environment. Ensure you have:

  • Access credentials for the RHOAI dashboard

  • A web browser to access the RHOAI dashboard

  • Access credentials for the OpenShift web console

Also ensure that you already deployed MLflow and EvalHub by following the instructions from the previous chapter.

Instructions

In this lab, you will perform a quick evaluation run using the RHOAI dashboard and view its results in MLflow.

As you perform this activity, you will alternate between three windows:

  • The Red Hat OpenShift AI (RHOAI) dashboard

  • The Red Hat OpenShift web console

  • A terminal window

Retrieve model name and endpoint, and label its project for TrustyAI

  1. Find the name and endpoint of the model to evaluate.

    1. Open the RHOAI dashboard and, in its left pane, select AI hub  Models and select the Deployments tab. There is a single row, named llama-32-3b-instruct.

    2. Click its Internal endpoint link to raise a pop-up displaying its URL and click the copy icon to copy its URL to the clipboard.

    3. Also take note of the model name, which is llama-32-3b-instruct, for use in the next step.

  2. Label your project for TrustyAI network policies.

    1. Open the OpenShift web console and select Administration  Namespaces. Enter my in the search field and click my-first-model.

      You cannot change namespace labels by using Home  Projects. It seems to work, but the namespace resource associated with the project will remain unchanged.

    2. Click the Actions  Edit labels and, in the Edit labels popup, append evalhub.trustyai.opendatahub.io/tenant=true. Do not remove any of its other labels!

    3. Click Save.

Submit an evaluation job using the RHOAI dashboard

  1. Find a quick benchmark to run.

    1. Switch to the RHOAI dashboard and, in its left navigation pane, select Develop & train  Evaluations.

    2. Click Create new evaluation and, on the New evaluation run page, click Single benchmark.

    3. In Single benchmark page, select Name in the filter, and enter quick in the search field. You should see three benchmarks, each with a different label of Safety, Performance, and Security.

    4. Click Quick security smoke test to open a right pane with details of that benchmark. Verify that this benchmark comes from the Garak evaluation framework, which is unlikely to require large data sets from HuggingFaces.

  2. Submit an evaluation job for the Quick security smoke test benchmark.

    1. In the left pane, select Develop & train  Evaluations and, in the Project field, enter my and select my-first-model.

    2. Click Single benchmark, select Name and enter quick. In the Quick security smoke test card, click Use this benchmark.

    3. Enter garak-quick in the Evaluation name field and, in the Create new experiment field, enter garak-evalhub

      There is an issue with the RHOAI dashboard which prevents it from retrieving names of existing experiments with MLflow. You must always create a new experiment, and ensure the name does not match any existing experiment in the same project nor the name of experiments that were marked for deletion. If you use the EvalHub CLI, you can either add to existing experiments or create new ones.

    4. Enter llama-32-3b-instruct in the Model or agent name field, and paste the URL you copied in the previous step in the Endpoint URL field. Append /v1 to the URL so it is a valid OpenAI endpoint. The model is not configured to require authentication, so there is no need to provide an API key.

    5. Click Start evaluation run. You should see a message Evaluation "garak-quick" has been started.

      If there is any error, the error message might disappear before you can read it and it might seem that nothing happened. In that case, try starting the the evaluation run again, without making changes.

  3. Monitor the evaluation job.

    1. You should be still on the Evaluations page, which now displays a single row named garak-quick with a Pending status. Be patient while EvalHub downloads the container images required by the bebchmark.

    2. Once the evaluation run starts, it should terminate very quickly, and you are likely to not see its Running status, but only see it transition to Complete. If it takes more than a few minutes without any change, refresh your RHOAI dashboard page.

    3. Click garak-quick to review details of the evaluation run. That evaluation is expected to fail. Notice that its metrics indicate only one attack was attempted and it was successful. It’s a common attack of "asking a model to do something it shouldn’t do", which you would prevent, in production deployments, by enabling guard rails.

    4. Optionally, you can switch to the OpenShift web console and enter Workloads  Jobs to monitor Kubernetes jobs in the my-first-model project. Notice that the name of the Job contains the ID of the EvalHub evaluation run, which unfortunately you cannot get from the RHOAI dashboard. You can also click 1 of 1 under Completions to view the Kubernetes pod managed by the job.

View evaluation results on MLflow

  1. View the two experiments from EvalHub in MLflow.

    1. Return to the RHOAI dashboard and, in its left navigation pane, select Develop & train  Experiments (MFflow). In the Projects field, enter my and select my-first-model.

    2. The experiments page should display a single experiment. Click garak-evalhub.

    3. In Experiments page for the garak-evalhub experiment, click Evaluation runs. It should display two runs, and their names match their EvalHub evaluation IDs. Click the one with a green ball, which is the most recent and corresponds to the second experiment, that got a Pass score.

    4. That experiment contains no metrics, but select its Overview tab to visualized the same metrics you seen with the EvalHub CLI or with the Evaluations page of the RHOAI dashboard.

Summary

You performed two evaluation runs, using the Garak provider or evaluation framework: once using the RHOAI dashboard, and other using the EvalHub CLI. Then you visualized their results using both EvalHub and MLflow.
