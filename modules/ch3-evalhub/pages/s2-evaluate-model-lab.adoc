= Lab: Evaluate a Self-Hosted Model

Objective::

Run evaluation jobs on a self-hosted model using EvalHub, monitor their progress, and inspect results and metrics from the RHOAI dashboard.

== Before you begin

You need access to the predeployed Red Hat OpenShift AI (RHOAI) instance provided in your lab environment. Ensure you have:

* Access credentials for the RHOAI dashboard
* A web browser to access the RHOAI dashboard
* Access credentials for the OpenShift web console

Also ensure that you already deployed MLflow and EvalHub by following the instructions from the xref:ch2-deployment:index.adoc[previous chapter].

== Instructions

In this lab, you will perform a quick evaluation run using the RHOAI dashboard and view its results in MLflow.

As you perform this activity, you will alternate between three windows:

* The Red Hat OpenShift AI (RHOAI) dashboard
* The Red Hat OpenShift web console
* A terminal window

=== Retrieve model name and endpoint, and label its project for TrustyAI

1. Find the name and endpoint of the model to evaluate.

.. Open the RHOAI dashboard and, in its left pane, select menu:AI hub[Models] and select the menu:Deployments[] tab. 
There is a single row, named menu:llama-32-3b-instruct[].

.. Click its menu:Internal endpoint[] link to raise a pop-up displaying its URL and click the menu:copy[] icon to copy its URL to the clipboard.

.. Also take note of the model name, which is `llama-32-3b-instruct`, for use in the next step.

2. Label your project for TrustyAI network policies.

.. Open the OpenShift web console and select menu:Administration[Namespaces].
Enter `my` in the search field and click menu:my-first-model[].
+
WARNING: You _cannot_ change namespace labels by using menu:Home[Projects].
It seems to work, but the namespace resource associated with the project will remain unchanged.

.. Click the menu:Actions[Edit labels] and, in the *Edit labels* popup, append `evalhub.trustyai.opendatahub.io/tenant=true`.
Do not remove any of its other labels!

.. Click menu:Save[].

=== Submit an evaluation job using the RHOAI dashboard

[start=3]
3. Find a quick benchmark to run.

.. Switch to the RHOAI dashboard and, in its left navigation pane, select menu:Develop & train[Evaluations].

.. Click menu:Create new evaluation[] and, on the *New evaluation run* page, click menu:Single benchmark[]. 

.. In the *Single benchmark* page, select menu:Name[] in the filter, and enter `quick` in the search field.
You should see three benchmarks, each with a different label of *Safety*, *Performance*, and *Security*.

.. Click menu:Quick security smoke test[] to open a right pane with details of that benchmark.
Verify that this benchmark comes from the Garak evaluation framework, which is unlikely to require large data sets from Hugging Face.

4. Submit an evaluation job for the `Quick security smoke test` benchmark.

.. In the left pane, select menu:Develop & train[Evaluations] and, in the menu:Project[] field, enter `my` and select menu:my-first-model[].

.. Click menu:Single benchmark[], select menu:Name[] and enter `quick`.
In the menu:Quick security smoke test[] card, click menu:Use this benchmark[].

.. Enter `garak-quick` in the *Evaluation name* field and, in the *Create new experiment* field, enter `garak-evalhub`
+
NOTE: There is an issue with the RHOAI dashboard that prevents it from retrieving names of existing experiments with MLflow.
You must always create a new experiment and ensure the name does not match any existing experiment in the same project or the name of experiments that were marked for deletion in MLflow.
If you use the EvalHub CLI, you can either add to existing experiments or create new ones.

.. Enter `llama-32-3b-instruct` in the *Model or agent name* field, and paste the URL you copied in the previous step in the *Endpoint URL* field.
Append `/v1` to the URL so it is a valid OpenAI endpoint.
The model is not configured to require authentication, so there is no need to provide an API key.

.. Click menu:Start evaluation run[].
You should see a message `Evaluation "garak-quick" has been started.`
+
NOTE: If there is any error, the error message might disappear before you can read it and it might seem that nothing happened.
In that case, try starting the evaluation run again, without making changes.

5. Monitor the evaluation job.

.. You should still be on the *Evaluations* page, which now displays a single row named menu:garak-quick[] with a `Pending` status.
Be patient while EvalHub downloads the container images required by the benchmark.

.. Once the evaluation run starts, it should terminate very quickly, and you are likely to _not_ see its `Running` status, but only see it transition to `Complete`.
If it takes more than a few minutes without any change, refresh your RHOAI dashboard page.

.. Click menu:garak-quick[] to review details of the evaluation run.
That evaluation is expected to fail.
Notice that its metrics indicate only one attack was attempted and it was successful.
It is a common attack of "asking a model to do something it should not do", which you would prevent, in production deployments, by enabling guardrails.

.. Optionally, you can switch to the OpenShift web console and select menu:Workloads[Jobs] to monitor Kubernetes jobs in the `my-first-model` project.
Notice that the name of the job contains the ID of the EvalHub evaluation run, which unfortunately you _cannot_ get from the RHOAI dashboard.
You can also click menu:1 of 1[] under *Completions* to view the Kubernetes pod managed by the job.

=== View evaluation results on MLflow

[start=8]
8. View the two experiments from EvalHub in MLflow.

.. Return to the RHOAI dashboard and, in its left navigation pane, select menu:Develop & train[Experiments (MLflow)].
In the menu:Projects[] field, enter `my` and select menu:my-first-model[].

.. The experiments page should display a single experiment.
Click menu:garak-evalhub[].

.. In the *Experiments* page for the `garak-evalhub` experiment, select menu:Evaluation runs[]. 
It should display two runs, and their names should match their EvalHub evaluation IDs.
Click the one with a green ball, which is the most recent and corresponds to the second evaluation run, that received a `Pass` score.

.. That experiment contains no metrics, but select its menu:Overview[] tab to visualize the same metrics you saw with the EvalHub CLI or with the *Evaluations* page of the RHOAI dashboard.

=== Summary

You performed two evaluation runs, using the Garak evaluation framework: first using the RHOAI dashboard, and then using the EvalHub CLI.
Then you visualized their results using both EvalHub and MLflow.
